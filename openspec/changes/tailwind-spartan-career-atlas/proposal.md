# Proposal: Tailwind + Spartan Career Atlas

## Intent

Tailwind v4 must be the runtime-verifiable composition system; the journey must render maintained Spartan Brain Progress with copied Helm styles. A custom/native substitute is unacceptable.

## Scope

### In Scope
- Run official Spartan discovery and complete missing setup; missing config is setup work.
- Add the minimum official Brain dependency and copied Helm Progress files/styles for genuine runtime rendering.
- Move landing composition to Tailwind utilities; delete replaceable BEM CSS.
- Bind passive progress to existing intro → experience → projects → assistant state. It shows status but never navigates, focuses, unlocks, or changes content.
- Preserve Continue-only advancement, next-section focus, relock, unlock, and persistent chat return.
- Retain documented CSS only for tokens, specialized pseudo/focus, and complex reduced-motion rules.

### Out of Scope
- Backend, Supabase, Resend, contact persistence, or cross-session unlock storage.
- Native/custom progress fallbacks, conventional navbar, glassmorphism, gradients, carousels, or reading-blocking animation.
- Motion by default; it may be admitted only for decorative use after bundle, reduced-motion, and cleanup validation.

## Capabilities

### New Capabilities
- None.

### Modified Capabilities
- `guided-portfolio-experience`: require Tailwind template composition and runtime Brain Progress/Helm while retaining passive progress and explicit advancement.
- `grounded-portfolio-chat`: retain intentional embedded chat focus/relock while journey state represents readiness.

## Approach

Use official discovery, then add only Brain Progress and copied Helm styles. `JourneyPage`'s signal remains the status source and Continue remains the only transition API. Prove rendered utilities and Brain/Helm runtime output.

## Affected Areas

| Area | Impact | Description |
|---|---|---|
| `frontend/src/app/features/journey/` | Modified | Utility-first landing and passive Brain/Helm progress |
| Shared/chat templates and `styles.css` | Modified | Utility migration and CSS exceptions |
| `frontend/package.json`, lockfile, Spartan files | Modified/Create | Minimum official Progress setup |
| Focused specs and Playwright | Modified | State, focus, relock, motion, viewport evidence |

## Acceptance Boundaries

- Brain Progress plus Helm styles MUST import and render in runtime; no fake wrapper or equivalent native bar.
- Progress is accessible and observable, but cannot advance/relock/unlock/focus/navigate.
- Tests cover progress, Continue/focus, reload/relock, and reduced motion; verify includes desktop/390px and PID cleanup.
- Build remains within 500 kB warning / 1 MB error and 4/8 kB style limits.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Decorative migration or fake setup | Medium | Inspect templates and runtime output |
| CSS/bundle growth | Medium | Minimal files; reject optional Motion |

## Delivery Implications

Likely exceeds the 400-line review budget. With `ask-on-risk`, tasks must forecast this and request stacked-to-main work-unit slices if high risk is confirmed.

## Rollback Plan

Revert Spartan setup, Helm files, utility migration, and coupled tests as one visual work unit; journey state and backend remain untouched.

## Success Criteria

- [ ] Runtime proves genuine Brain Progress with Helm styling and Tailwind v4 template utilities.
- [ ] Journey, focus, relock, lock, and chat-return contracts remain intact.
- [ ] CSS exceptions and accessibility/budget evidence are recorded.
